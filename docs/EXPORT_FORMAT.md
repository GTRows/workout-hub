# WorkoutHub Full-Export JSON Format

This document is the source of truth for the shape of
`GET /api/export/full` and `POST /api/export/import`.

## Intended use

The schema is designed so a human can hand an export file to a chat-style
LLM (Claude, ChatGPT, etc.), ask it to edit or generate a slice, then
hand the result back to WorkoutHub via the restore upload control.

Keep that workflow in mind when editing this document or the DTOs:

- Fields must be self-describing. Prefer readable names over cryptic
  acronyms.
- Every enum value is documented below so an LLM can reliably pick a
  legal value from a free-text user request.
- UUIDs may be regenerated by the LLM — import treats a missing `id`
  as "insert a fresh row" and a present `id` as "overwrite-or-insert at
  this id". Cross-row references (session -> workout_day_id, set ->
  exerciseId, day-exercise -> exerciseId) must line up with the ids the
  payload (or the existing catalog) carries.
- Timestamps are RFC 3339 UTC (`2026-04-23T14:05:00Z`). Dates are
  `YYYY-MM-DD`. Times are `HH:MM:SS`.

## Top-level envelope

```jsonc
{
  "schemaVersion": 1,            // integer, currently 1; import rejects other versions
  "exportedAt": "2026-04-23T14:05:00Z",
  "user": { ... },               // UserSection, nullable
  "plans": [ ... ],              // PlanSection[]
  "sessions": [ ... ],           // SessionSection[]
  "bodyMetrics": [ ... ],        // MetricRow[]
  "supplements": [ ... ]         // SupplementRow[]
}
```

All array fields are required; use `[]` for an empty slice. `user` may
be `null` if an LLM should not touch profile data.

## UserSection

```jsonc
{
  "id": "uuid",                  // ignored by import; principal owns the row
  "email": "fatih@example.com",  // ignored by import
  "displayName": "Fatih",
  "heightCm": 180,               // integer cm, nullable
  "weightKg": 78.5,              // decimal kg, nullable
  "birthDate": "1990-05-01",     // YYYY-MM-DD, nullable
  "gender": "male",              // free text (not enum), nullable
  "healthNotes": "free text",    // nullable
  "goals": "free text"           // nullable
}
```

## PlanSection

```jsonc
{
  "id": "uuid",                  // optional; preserved on re-import
  "name": "Starting 5x5",
  "active": true,                // exactly one active plan allowed per user
  "days": [ DayRow, ... ]
}
```

### DayRow

```jsonc
{
  "id": "uuid",                  // optional
  "dayOfWeek": 1,                // 1 = Monday, 7 = Sunday (ISO)
  "name": "Push Day",
  "focus": "push",               // see Enum: WorkoutFocus
  "estimatedDurationMin": 60,    // integer, nullable
  "exercises": [ DayExerciseRow, ... ]
}
```

### DayExerciseRow

```jsonc
{
  "id": "uuid",                  // optional
  "exerciseId": "uuid",          // MUST reference an existing row in the exercises catalog
  "orderIndex": 0,               // zero-based ordering within the day
  "targetSets": 3,
  "targetRepsMin": 8,            // nullable
  "targetRepsMax": 10,           // nullable
  "targetWeightKg": 80.0,        // nullable
  "restSeconds": 120,            // nullable
  "notes": "slow eccentric"      // nullable
}
```

## SessionSection

```jsonc
{
  "id": "uuid",                  // optional
  "workoutDayId": "uuid",        // nullable (ad-hoc session)
  "startedAt": "2026-04-23T09:00:00Z",
  "endedAt": "2026-04-23T10:05:00Z",  // nullable (active session)
  "notes": "felt strong",        // nullable
  "mood": 4,                     // 1-5 integer, nullable
  "energyLevel": 3,              // 1-5 integer, nullable
  "sets": [ SetRow, ... ]
}
```

### SetRow

```jsonc
{
  "id": "uuid",                  // optional
  "exerciseId": "uuid",          // MUST reference the exercises catalog
  "setNumber": 1,                // 1-based per (session, exercise)
  "repsDone": 8,
  "weightKg": 80.0,              // nullable (bodyweight movements)
  "rpe": 8,                      // 1-10 scale, nullable
  "completed": true,
  "notes": "free text"           // nullable
}
```

## MetricRow (body measurements, one row per recorded_date per user)

```jsonc
{
  "id": "uuid",                  // optional
  "recordedDate": "2026-04-23",  // unique per user
  "weightKg": 78.5,              // nullable
  "bodyFatPercent": 18.5,        // 0-100, nullable
  "waistCm": 82.0,               // nullable
  "chestCm": 100.0,              // nullable
  "armCm": 36.0,                 // nullable
  "thighCm": 58.0,               // nullable
  "photoUrl": "https://...",     // nullable
  "notes": "morning, fasted"     // nullable
}
```

## SupplementRow

```jsonc
{
  "id": "uuid",                  // optional
  "name": "Creatine",
  "dosage": "5g",                // free text, nullable
  "timing": "morning",           // see Enum: SupplementTiming
  "active": true                 // retired supplements set to false
}
```

## Enums

### WorkoutFocus

`push`, `pull`, `legs`, `cardio`, `core`, `full_body`, `rest`

### SupplementTiming

`morning`, `pre_workout`, `post_workout`, `evening`, `with_meal`, `other`

## Import semantics

Importing via `POST /api/export/import` replaces each slice wholesale:

1. `user` profile fields are overwritten (non-null fields only).
2. `bodyMetrics`: existing rows for the caller are deleted, then the
   payload rows are inserted.
3. `supplements`: existing rows deleted then inserted.
4. `sessions`: existing sessions (and their sets) deleted; payload
   sessions inserted.
5. `plans`: existing plans (cascading days + day_exercises) deleted;
   payload plans inserted. The payload may contain at most one plan
   with `"active": true`.

`exerciseId` references must match rows already present in the
`exercises` catalog. The catalog itself is not exported or imported —
it is shared and administratively managed.

## Minimal example

The smallest valid payload contains just the schema envelope. Import
succeeds and becomes a no-op (empty replacements):

```json
{
  "schemaVersion": 1,
  "exportedAt": "2026-04-23T00:00:00Z",
  "user": null,
  "plans": [],
  "sessions": [],
  "bodyMetrics": [],
  "supplements": []
}
```
