# Milestone v0.6: Operational Maturity

**Status:** SHIPPED 2026-05-09
**Phases:** 31-37 (7 phases, 11 plans)
**Total Plans:** 11
**Releases:** v0.6.0

## Overview

Real-world hardening for daily use - charts/stats surface re-composition on `/insights`, PWA install prompt + offline shell + service-worker scope hardening, web push notifications wired end-to-end through the existing backend push package, server-scheduled rest-timer push for backgrounded sessions, frontend-side Prometheus HTTP metrics closing carried-forward i-4, uniform loading skeletons + error boundaries + Web Vitals reporter + perf-budget doc on the (app) shell, and the structured-logging test redesign closing carried-forward i-9. Seven phases (31-37) across 11 plans (six single-plan phases + Phase 36 split into three sub-plans). v0.6.0 ships with the full Operational Maturity surface: client-rendered weight trend / PR teaser / range toggles / locale-aware tooltips on `/insights`, an install-prompt card on the dashboard, a localized `/offline` shell behind a versioned service-worker cache (v3 in Phase 33), per-user Web Push subscriptions with a self-test endpoint, server-side rest-timer schedules dispatched via Web Push and cancelled on next-set / finish / unmount, hand-rolled per-route HTTP request count + duration histogram and per-route Web Vitals histograms exposed on `/api/metrics`, RouteSkeleton + RouteError + global-error.tsx wired across all 15 (app) segments, and a `StructuredLoggingTest` that boots the full `WorkoutHubApplication` under `@ActiveProfiles("prod")` so prod ECS JSON + deny-list masking are CI-asserted on every build.

## Milestone Summary

**Decimal Phases:** None. v0.6 stayed inside the planned phase numbering (31-37); no inserted decimal phases were needed because the audit step (Phase 21) that drove v0.5's decimals was a v0.5-specific scoping pass.

**Key Decisions (locked-in 2026-05-09):**

- All v0.3 + v0.4 + v0.5 locked-in decisions carry forward unchanged. Full prior decision logs live in the v0.3 / v0.4 / v0.5 milestone archives.
- Insights surface composition: `/insights` is the canonical "Detayli insight sayfasi" deliverable from ProjectBrief Phase 6, NOT a separate `/stats` route. WeightTrendCard is mounted at the top, PrTeaserCard at the bottom; the remaining four ProjectBrief Phase 6 charts (volume, 1RM, heatmap, streak) stay in their existing slots and gain the locale-aware tooltip + range toggle. Splitting `insights-client.tsx` into per-card files is deferred to v1.0 polish (file size overflow accepted at ~280 lines per the `export-client.tsx` Phase 30-01 precedent).
- PWA install UX scope: Chromium-family browsers only (`beforeinstallprompt` is the contract). iOS Safari needs a separate instructions sheet; deferred to a hypothetical 32-02 follow-up only if user feedback demands it (homelab tailnet-only audience predominantly uses Chrome / Edge / Firefox-Android).
- localStorage namespacing: `wh.<feature>.<key>` per the Phase 25 offline queue convention. The PWA dismiss flag lives at `wh.installPromptDismissed`; cleared on `appinstalled` so a reinstall surfaces the prompt again.
- Service-worker cache versioning: bump the `CACHE` constant on every behaviour-affecting SW change (v1 -> v2 in Phase 32; v2 -> v3 in Phase 33 for the new push + notificationclick handlers). The activate handler already deletes any cache name that does not match the current `CACHE`, so v-bumping is the only operator-side migration.
- Web Push schedule contract: server-scheduled rest-timer push is the primary path because service workers cannot persist a `setTimeout` across termination (Chrome ~30s, Safari almost immediately) and `TimestampTrigger` is Chromium-only behind a flag. The client foreground `setInterval` UI stays as the visible-tab path; both channels coalesce via `tag: "wh-reminder"` + `renotify: false` from Phase 33.
- Rest-timer schedule lifecycle: cancel + re-schedule is the contract (no edit / reschedule). Cancellation is fire-and-forget with `.catch(noop)`; a failing DELETE never blocks the set-submit flow. Foreground in-page timer stays operational regardless of network outcome.
- Frontend metrics dependency posture: `prom-client` and `@opentelemetry/sdk-metrics` rejected because `frontend/package.json` is protected. Hand-rolled in-memory registry is the load-bearing decision; works under Next.js standalone single-process deploy. Counter / histogram reset on container restart matches the standard Prometheus contract for non-restorable counters and aligns with the existing `process_*` gauge behaviour.
- Web Vitals reporter dependency posture: framework-native `next/web-vitals` re-export is used (ships inside the `next` package, no `web-vitals` direct dep needed). The reporter mounts in the root layout so it fires once per page load on every authenticated render.
- Perf-budget delivery: doc-only in v0.6 (`docs/PERF_BUDGETS.md`). Lighthouse CI workflow + `scripts/check-bundle-size.mjs` + `@next/bundle-analyzer` dep all rejected because they would each touch a protected path; deferred as ISSUES.md i-15 with a clear trigger ("operator approves at least one protected-file edit, OR Phase 38+ takes ownership of CI perf gating").
- Loading + error UX uniformity: 15 `loading.tsx` + 15 `error.tsx` + 1 `global-error.tsx` covering every (app)-group segment. The shared `RouteSkeleton` and `RouteError` components live under `frontend/src/components/` and reuse the `common.loading/error/errorHint/tryAgain/goHome` i18n keys. Per-route customization is deferred to future polish; the uniform UX is the v0.6 deliverable.
- Structured logging test posture: extend `AbstractIntegrationTest` so the test boots the real `WorkoutHubApplication` and shares the reusable Testcontainers Postgres with the rest of the integration suite. `@WebEnvironment.NONE` is the right runtime mode (no servlet container needed; logging emission happens via direct SLF4J `Logger.info` calls). `OutputCaptureExtension` stays the only viable stdout-capture mechanism; a `@BeforeEach`-based `System.setOut` swap demonstrably fails for Logback structured output and was rejected at plan time.
- Local Maven not installed on this Windows host; backend tests run only in CI (carried from v0.3 + v0.4 + v0.5). v0.6 plans skip the local `mvn verify` gate and delegate to CI; the new `RestTimerScheduler` Testcontainers integration test (Phase 34) and the redesigned `StructuredLoggingTest` (Phase 37) are the load-bearing structural CI gates.
