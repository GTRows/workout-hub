**Status:** SHIPPED 2026-05-07

## Overview

Complete the backend modules from `ProjectBrief.md` Phases 3-5 - workout plan editing, live session execution, body metrics, full export refinement - close the disabled-test debt carried from v0.3 (i-1, i-2), and stand up the OpenAPI contract documentation surface so frontend / external clients have a CI-asserted machine-readable reference. Eight phases (13-20) covering workouts audit, workouts hardening, sessions core, sessions analytics, body metrics, export refinement, API contract docs, and the release cut. v0.4.0 ships with a SpringDoc 2.6.0 runtime OpenAPI document at `GET /v3/api-docs` + Swagger UI at `GET /swagger-ui.html`, two new Flyway migrations (V26 clientSetId, V27 is_pr), 14 new endpoints across the analytics + body-metrics slices, snake_case `ClaudeSummaryDto` aligning the LLM-paste surface with the ProjectBrief example, and round-trip-stable full-export with the new `is_pr` wire field.

## Post-Release Patch Window

The v0.4.0 release tag fired the release workflow successfully but a small fix bundle landed on `main` shortly after to close late-discovered runtime gaps surfaced by the new SpringDoc surface and the `@Disabled` test re-enables:

- `chore(api-docs)` (commit `c1b95f7`): Worked around the SpringDoc 2.6.0 vs Spring Boot 3.5.x `ControllerAdviceBean(Object)` constructor break by disabling the override-with-generic-response scan and registering `ApiError` schemas via `OpenApiCustomizer`; restores `GET /v3/api-docs`. Tracked as ISSUES.md i-13 (revert workaround when SpringDoc bumps to >= 2.7).
- `fix(export)` (commit `d3d83d8`): Dropped ID preservation in full-export import to avoid the Hibernate detached-entity trap when re-inserting plans/days with assigned UUIDs; rewrites `session.workoutDayId` references via a payload-to-DB UUID map to keep round-trip referential integrity.
- `fix(sessions)` (commit `ddc4785`): Stripped the `newPr` JSON field from idempotent `clientSetId` replay responses; the field is a fresh-write signal and was leaking on retry, breaking `SessionSetsIntegrationTest.sameClientSetIdRetryReturns200WithSameId`.

## Milestone Summary

**Decimal Phases:** None.

**Key Decisions (locked-in 2026-05-04..05-07):**

- All v0.3 locked-in decisions carry forward unchanged (Renovate-pin update model, parametric `BIND_ADDR` default `127.0.0.1`, multi-arch GHCR images, no `:latest`, JSON ECS production logging, built-in JWT default + forward-auth opt-in, no OIDC client code, etc.). Full v0.3 decision log lives in `.planning/milestones/v0.3-ROADMAP.md` "Key Decisions" section.
- SpringDoc artifact: Option A1 single starter (`org.springdoc:springdoc-openapi-starter-webmvc-ui`); the api-only artifact alongside is redundant. Bundled UI per Direction D1 with `BIND_ADDR=127.0.0.1` as the trust boundary (operators choose proxy-side restriction if they need stricter discoverability).
- SpringDoc version pin: conservative `2.6.0`. SpringDoc 2.7+ would call Spring 6.2's removed `ControllerAdviceBean(Object)` constructor cleanly, but the 2.7+ bump introduces a transitive change shortly before release; safer to ship 0.4.0 with the targeted `OpenApiCustomizer` workaround and bump the dep in a follow-up patch (tracked as i-13).
- ClaudeSummary naming convention: Direction C per-record `@JsonNaming(SnakeCaseStrategy)` on `ClaudeSummaryDto` and its 9 nested records ONLY; `FullExportDto`, `ImportResultDto`, `CsvImportResultDto` stay camelCase to preserve backup-restore round-trip on prior payloads. First `@JsonNaming` usage in `backend/src`.
- PR durability: persist `is_pr` via V27 with window-function backfill (`ROW_NUMBER() OVER (PARTITION BY user_id, exercise_id ORDER BY weight*(1 + reps/30) DESC)`). Closes the create-vs-reread newPr flag gap from Phase 15-04 with a stronger durable-read assertion.
- Body-metrics status-code direction: Direction A (`MetricsService.UpsertResult(BodyMetricDto dto, boolean wasCreated)` wrapper; controller maps `wasCreated ? 201 : 200`). V6 UNIQUE-by-`(user, date)` encodes date-keyed identity by design; rejects Direction B (POST + PUT-by-id split).
- Body-metrics time-series direction: Option 1 (extend `GET /api/metrics` with optional `from`/`to` `LocalDate` query params reusing `idx_body_metrics_user_date`); chart-projection endpoint Option 2 deferred to Phase 28 / Phase 31.
- ApiError typed `code` curation: hand-write `@Schema(allowableValues = {...})` enumerating the 4 Phase-15-04 codes; `ApiErrorCode` Java enum extraction deferred to Phase 42 (the durable fix for i-NEW-A drift risk).
- 28 user/admin-facing controllers carry hand-curated `@Tag(name = ..., description = ...)` per Option B2; the 3 operator controllers (`HealthController`, `PrometheusMetricsController`, `ScaleWebhookController`) stay untagged.
- `paths-to-match=/api/**` excludes `/livez`, `/healthz`, `/metrics`, `/actuator/**`, `/error` from the public OpenAPI surface; operator paths stay documented in `docs/OBSERVABILITY.md`.
- Local Maven not installed on this Windows host; backend tests run only in CI (carried from v0.3). Plans skip the local `mvn verify` gate and delegate to CI; the new `OpenApiSurfaceIntegrationTest` is the load-bearing structural CI gate for the SpringDoc + Boot 3.5 integration.

**Technical Debt Incurred:**

- `OpenApiConfig` carries the SpringDoc 2.6.0 vs Spring Boot 3.5.x `ControllerAdviceBean(Object)` workaround (disabled override-with-generic-response scan + `OpenApiCustomizer` registration of `ApiError` schemas). Revert this when i-13 lands and SpringDoc bumps to >= 2.7.

The durable mitigation is `ApiErrorCode` Java enum extraction (Phase 42 candidate).
