# Milestone v0.5: Frontend Completion

**Status:** SHIPPED 2026-05-09
**Phases:** 21-30 (10 main + 3 inserted decimals: 22.5, 25.5, 29.5)
**Total Plans:** 19
**Releases:** v0.5.0

## Overview

Complete the frontend modules from `ProjectBrief.md` Phases 4-6 (frontend slice) - inventory the existing app shell, then deliver the user-facing surfaces end-to-end: auth pages with typed-error UX and logout/session-expired handling, a typed `ApiError.code` helper wired across client mutations, the dashboard (today card + weekly summary + last weight), the weekly plan editor with drag-drop reorder, the session-execution screen with `clientSetId` UUID idempotency + IndexedDB drain wired to the v0.4 sync contract + typed 409 UX + RPE/edit/delete, Zod schema parity for the remaining backend response surfaces, the exercise-catalog detail with PR card + progress chart, history view with Repeat-workout CTA, metrics UI with the 200/201 toast split, profile settings with load-error banners + a11y polish, the middleware-matcher route-coverage gate for `/achievements`, and the export/import UI with destructive-import confirm gate + bounded export-history shim. Thirteen phases (21-30, plus inserted decimals 22.5 / 25.5 / 29.5) across 19 plans. v0.5.0 ships with the full app shell rendering on Next.js 15 + React 19 + Tailwind v4 + shadcn/ui + TanStack Query + Zod, the offline-first session queue cleanly draining via the v0.4 `clientSetId` idempotency contract, the first-ever `frontend/src/middleware.test.ts` suite gating route coverage drift, and Netty pinned to `4.1.133.Final` (override) to close CVE-2026-42583/42584/42587 via a same-day patch window.

## Milestone Summary

**Decimal Phases:** Three (22.5 typed-apierror-helper, 25.5 zod-schemas, 29.5 middleware-matcher-gap), all inserted from the 21-01 audit Section 6 net-new phase rows. Each closed in a single plan.

**Key Decisions (locked-in 2026-05-07..05-09):**

- All v0.3 + v0.4 locked-in decisions carry forward unchanged. Full prior decision logs live in the v0.3 + v0.4 milestone archives.
- Frontend offline-first contract: Dexie IndexedDB queue scoped to the session-execution flow drains on the `online` event using `clientSetId` UUID as the primary idempotency key (Phase 25-01 + 25-02). The drain has a permanent-reject branch for unrecoverable errors (Phase 25-02). Replay yields 200; newly created yields 201; the `clientSetId` round-trips with the v0.4 backend `clientSetId` column on `session_sets` per the V26 migration.
- Frontend route protection model: `frontend/src/middleware.ts` enumerates 12 (app)-group top-level segments in two parallel structures - `PROTECTED_PREFIXES` (runtime check) and `config.matcher` (compile-time scope) - that must stay in lockstep. Drift between the two arrays is the bug that Phase 29.5 fixed at the source and that the new `middleware.test.ts` suite gates going forward via a hand-curated `EXPECTED_PROTECTED_ROUTES` list.
- Typed ApiError consumption: the frontend branches on the v0.4 backend `ApiError.code` typed enum (Phase 22.5 helper). Tooling and UI must branch on `status + code`, not `message`. The current 4-value catalog (SESSION_ALREADY_ACTIVE / SESSION_ALREADY_FINISHED / SESSION_FINISHED / SET_NUMBER_DUPLICATE) lives in two places (the runtime throw sites under `sessions/` AND the `@Schema(allowableValues = ...)` annotation on `ApiError.java`); the durable mitigation is the Phase 42 `ApiErrorCode` Java enum extraction (carried from v0.4 technical-debt log).
- Zod schema parity for v0.4 backend response surfaces: `ImportResult`, `FullExport`, vapid, and push subscribe surfaces all round-trip via Zod schemas in the frontend (Phase 25.5). Future endpoint additions in v0.6+ should mirror this pattern.
- Export-history shim: bounded `localStorage`-backed shim with `useSyncExternalStore` snapshot caching (Phase 30-01). Frontend-only; no backend persistence (the JSON export endpoint is generated on demand and not persisted server-side per the v0.3 contract). The bounded entry count keeps localStorage usage low; the shim is intentionally not synced across devices.
- Destructive-import confirm gate: a confirm modal gates the import flow before any state-mutating call lands (Phase 30-01). This is the last-line UX gate for the multi-step import; the v0.4 backend `ImportValidator` rules (422 on stale `workoutDayId`, etc.) remain the authoritative gate.
- Local Maven not installed on this Windows host; backend tests run only in CI (carried from v0.3 + v0.4). Frontend tests run locally (vitest, Playwright deferred to v1.0 Phase 38). v0.5 plans skip the local mvn verify gate and delegate to CI.
- v0.5.0 stayed on Next.js 15 and `next-intl` 3 per i-6 + i-5 deferral; framework majors are deferred to v1.0 Phase 40. Phase 21 audit confirmed v0.5 work was achievable on the 15.x line without forcing the Next 16 migration.
- Netty pin: override to `4.1.133.Final` via the same-day patch window after the v0.5.0 tag closed CVE-2026-42583/42584/42587. The Netty 4.2 line bump is deferred to v0.6 Phase 41 (i-14) because it risks Spring Boot 3.5.x compatibility; CVE-2026-42577 is suppressed in trivy with no runtime path (Spring MVC + Tomcat).

**Technical Debt Incurred:**

- Carried-forward technical debt from v0.4 (SpringDoc 2.6.0 `ControllerAdviceBean` workaround in `OpenApiConfig`; hand-maintained `ApiError.code` typed-values catalog) remains open. v0.5 added no new backend Java debt.
- Frontend export-history shim (Phase 30-01) is `localStorage`-only with a bounded entry count; no cross-device sync. If the product later wants cross-device export history, a backend-persisted log endpoint is the durable fix; not in v0.5 scope.
- Frontend `EXPECTED_PROTECTED_ROUTES` list in `frontend/src/middleware.test.ts` is hand-curated. A future maintainer adding a new (app)-group route segment must update three places: the route file, both arrays in `middleware.ts`, and the test list. Auto-discovery would re-couple test logic to filesystem state and was rejected at plan time per the 29.5-01 plan's "Constraining Decisions" section.
- Netty CVE-2026-42577 trivy suppression (i-14): the `.trivyignore` entry must be removed when Phase 41 lands the Netty 4.2 bump; otherwise the suppression masks any future Netty CVEs that flow through the same advisory.
