## v1.1.1 Hot-fix (Shipped: 2026-05-11)

**Delivered:** Hot-fix release closing the v1.1.0 ship-blocker. The v1.1.0 release commit shipped without a green CI run; once the GHCR publish workflow tried to fire it surfaced multiple Spring Boot 4 + Jackson 3 + SpringDoc 3 + Next 16 + Lighthouse CI integration gaps that Phase 47-49 had asserted as closed but never actually CI-validated. v1.1.1 closes every one of them so `mvn verify` and the full CI matrix go green again. Released after `GTRows/workout-hub` was flipped from PRIVATE to PUBLIC visibility (Actions free-minute exhaustion on the private plan was blocking PR validation; public repos get unlimited Actions for free).

**Phases completed:** None (this is a non-roadmap hot-fix; not opened as a milestone in `.planning/ROADMAP.md`). Single PR `#32` with 5 fix commits + the release cut.

**Releases:** v1.1.1 (cut 2026-05-11 at sha `9cce9fa`; annotated tag `v1.1.1` pushed; Release workflow green; multi-arch GHCR images at `ghcr.io/gtrows/workouthub-{backend,frontend}:1.1.1`; draft GitHub Release awaiting maintainer-side Publish click per `IDENTITY.yaml#release.draft_first: true`).

**Key fixes:**

- Spring Boot 4 + Jackson 3 classpath: added `spring-boot-starter-jackson` opt-in dep to `backend/pom.xml`. Spring Boot 4 ships Jackson 2 by default; Jackson 3 is opt-in, so the codebase's `tools.jackson.databind` / `datatype.jsr310` / `core` imports never resolved at compile time and the v1.1.0 backend build failed in CI immediately.
- Spring Boot 4 modular autoconfigure split: added `spring-boot-starter-webmvc-test` (test scope) and `spring-boot-starter-flyway` deps; migrated 49 test files from `org.springframework.boot.test.autoconfigure.web.servlet.AutoConfigureMockMvc` to `org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc`. Without the Flyway starter, migrations never ran and Hibernate's schema validation failed on every test class with `missing table [achievements]`.
- Jackson 3 annotations namespace: reverted `JsonProperty` / `JsonAlias` / `JsonValue` / `JsonCreator` / `JsonInclude` imports across `JacksonConfig`, `SupplementTiming`, and `ScalePayload` from `tools.jackson.annotation.*` back to `com.fasterxml.jackson.annotation.*`. `jackson-annotations` keeps the legacy namespace in Jackson 3 by design for backward compatibility; Phase 47 incorrectly rewrote it.
- Jackson 3 ObjectMapper builder API: simplified `JacksonConfig.jacksonBuilderCustomizer` to `changeDefaultPropertyInclusion(incl -> incl.withValueInclusion(JsonInclude.Include.NON_NULL))`. ObjectMapper became immutable in Jackson 3 (`serializationInclusion()` removed); `JavaTimeModule` is built into `jackson-databind`; `WRITE_DATES_AS_TIMESTAMPS` moved to `DateTimeFeature` and now defaults to `false`.
- Spring Security 7 web config: added `@EnableWebSecurity` to `SecurityConfig`. The modular autoconfigure split no longer auto-exposes `HttpSecurity` from `spring-boot-starter-security` alone, so `securityFilterChain(HttpSecurity http)` failed to autowire and every Spring context with full web security failed to start.
- Hibernate 7 stricter flushing: `RestTimerScheduler.runOnce` calls `this.claimDueBatch()` directly, which bypasses Spring's `@Transactional` proxy. Hibernate 7 no longer silently flushes detached-entity dirty state on application shutdown like Hibernate 6 did, so `dispatchedAt` was never persisted. Replaced with explicit `repository.saveAll(due)`, which is correct regardless of proxy resolution.
- SpringDoc 3 + Spring Boot 4 schema scan: SpringDoc 3.0.x stops surfacing `@ControllerAdvice` `ExceptionHandler` response bodies in `components.schemas` even with `springdoc.override-with-generic-response=false`. Restored the pre-Phase-45 `OpenApiCustomizer apiErrorSchemaCustomizer` bean (the customizer fires after SpringDoc's scan) plus the `springdoc.override-with-generic-response: false` opt-out. Both Phase 45 deletions reverted; Phase 45's lock-in claim that "schemas surface via the framework default path" was wrong under SpringDoc 3.0.3 + Spring Boot 4.
- Lighthouse CI startServerCommand bug since Phase 49 ship: `.lighthouserc.cjs` had `startServerCommand: "pnpm --filter ./frontend start"`, but `lhci autorun` runs with cwd `frontend/`, so the filter resolved to `frontend/frontend/` and never started Next.js. Lighthouse then hit `localhost:3000` against nothing and surfaced as "Chrome prevented page load with an interstitial" on every PR run since Phase 49. Replaced with bare `pnpm start`. Also dropped `/_not-found` from the audited URL list (Next.js serves it with HTTP 404, which Lighthouse treats as `ERRORED_DOCUMENT_REQUEST`).
