This single plan delivers the audit's narrow scope: add three measurement inputs, plumb the upsert HTTP status through to the UI, and render distinct created-vs-updated toasts. There are no follow-up sub-plans for phase 28 — the audit verdict is "1 plan", and the deferred photo upload waits on v0.6's `/uploads` pipeline (Phase 32 or later).

Outputs:

1. **`frontend/src/lib/api/endpoints.ts` (MODIFIED) — extend `upsertMetric` to return both the parsed body and the HTTP status.**
   - Today the wrapper is `export async function upsertMetric(payload): Promise<BodyMetric>` (lines 423-432) and calls `api.request({ method: "POST", path: "/api/metrics", body, schema: bodyMetricSchema })`. `api.request<R>` returns `R` (the parsed body) and discards `Response.status` (`client.ts:99-136`).
   - Add a sibling helper `requestWithStatus<R>` in `client.ts` that returns `{ data: R; status: number }`, OR extend the existing `request` with an opt-in `returnStatus?: true` overload. Pick the overload approach — it keeps the existing `Promise<R>` callsites untouched and avoids introducing a parallel public function. Two TypeScript overload signatures:
     ```
     async function request<R>(opts: RequestOptions<R> & { returnStatus: true }): Promise<{ data: R; status: number }>;
     async function request<R>(opts: RequestOptions<R>): Promise<R>;
     ```
     The implementation captures `res.status` once before the existing `if (res.status === 204)` short-circuit and, when `opts.returnStatus === true`, wraps the existing return values as `{ data: ..., status: res.status }` (for the 204 branch, `data` is `undefined as R`).
   - Change `upsertMetric` signature to `Promise<{ metric: BodyMetric; created: boolean }>`. The `created` flag is `status === 201`. Anything else (200) is treated as `updated`. Status outside `{200, 201}` cannot reach this branch — the client throws an `ApiError` for non-2xx — so no defensive default.
   - Export an updated `UpsertMetricResult` type alias next to `UpsertBodyMetricPayload` (line 405).
   - No other endpoint helper changes. `client.ts` is the only shared file touched and the change is purely additive (existing single-return call sites continue to compile and pass tests).

The existing `jsonResponse(status, body)` helper is reused. The 4xx error path is unaffected — assert that an `ApiError` still throws under `returnStatus: true` (the third new case).

Extend the existing `<p className="text-muted-foreground">` to also surface waist/chest/arm/thigh when non-null using the same compact `· {value}cm` separator, e.g. `m.waistCm != null ? \` · ${m.waistCm}cm\` : ""`.    - Adapt `saveMutation.mutationFn` and `onSuccess`:
     - `mutationFn: (payload) => upsertMetric(payload)` — unchanged call shape; the destructured return is what's new.
