<objective>
Land the offline-first sync contract idempotency key on `POST /api/sessions/{sessionId}/sets`. A client-supplied `clientSetId` UUID becomes the authoritative idempotency token for the IndexedDB drainer: the same key replayed returns 200 with the persisted row; a different key with the same `(session_id, exercise_id, set_number)` still returns 409 as a true collision.

Purpose: Closes audit Section 4a's PARTIAL verdict. Today, 409 conflates "I already saved this" with "set_number collision," forcing the drainer at `frontend` to mark a queued row synced on every 409 - which silently swallows genuine numbering bugs. A UUID idempotency key makes 200 the unambiguous success signal for the drainer.
Output: V26 migration + entity field + repository lookup + service fast-path + controller status mapping (200 vs 201) + integration tests for retry, collision, and out-of-order drain ordering.
</objective>
