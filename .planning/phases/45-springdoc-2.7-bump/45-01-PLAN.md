## Goal

Bump `<springdoc.version>` from `2.6.0` to `2.8.17` (latest stable 2.x on Maven Central as of plan-author time, `<lastUpdated>20260412000033</lastUpdated>`) in `backend/pom.xml`, remove the v0.4 `ControllerAdviceBean` workaround (the `apiErrorSchemaCustomizer` `@Bean` in `OpenApiConfig.java` plus the `springdoc.override-with-generic-response: false` line in `application.yml`), close deferred issue **i-13** in `.planning/ISSUES.md`, and let the existing `OpenApiSurfaceIntegrationTest` (5 tests) validate that `/v3/api-docs` returns 200 and the ApiError schema + code-enum + security schemes + tag set survive the bump intact.

The roadmap line for Phase 45 reads "Phase 45: springdoc-2.7 - bump SpringDoc to 2.7+, remove ControllerAdviceBean workaround in OpenApiConfig (closes i-13)." Plan-author audit at HEAD (commit `931cb69`, 2026-05-09) found:

1. **SpringDoc 2.6.0 pin trace.** `backend/pom.xml` line 24 reads `<springdoc.version>2.6.0</springdoc.version>`; line 84 declares the `springdoc-openapi-starter-webmvc-ui` dependency at that version. The artifact entered the codebase via Phase 19-02 (per the i-13 entry in `.planning/ISSUES.md`).

2. **Workaround surface (twofold).** The v0.4 fix bundle (commit `c1b95f7` per the i-13 entry) workaround lives in two files:
   - `backend/src/main/resources/application.yml` line 92 sets `springdoc.override-with-generic-response: false`. The accompanying comment block (lines 86-91) explains: "SpringDoc 2.6.0's GenericResponseService scans @RestControllerAdvice via ControllerAdviceBean(Object), a constructor that Spring 6.2+ removed. Disabling override-with-generic-response skips that path so /v3/api-docs builds without crashing."
   - `backend/src/main/java/com/workouthub/common/config/OpenApiConfig.java` lines 67-87 declare an `apiErrorSchemaCustomizer` `OpenApiCustomizer` `@Bean` that manually re-registers `ApiError` + `ApiError.FieldError` schemas via `ModelConverters.getInstance().readAllAsResolvedSchema(ApiError.class)`. The Javadoc on lines 55-66 explains: "Normally SpringDoc 2.6.0 surfaces these via its GenericResponseService scan of @RestControllerAdvice exception handlers, but that path calls new ControllerAdviceBean(Object), a constructor Spring 6.2 removed. We disable that scan with springdoc.override-with-generic-response=false to keep /v3/api-docs from 500-ing, and manually re-register the error schemas here so the OpenAPI consumers (and our integration test) still see ApiError + ApiError.FieldError under components.schemas."

3. **Test contract.** `backend/src/test/java/com/workouthub/common/web/OpenApiSurfaceIntegrationTest.java` (5 tests) asserts: (a) `GET /v3/api-docs` returns 200 without auth, (b) `GET /swagger-ui.html` returns 3xx redirection, (c) `components.securitySchemes` declares both `bearerAuth` and `forwardAuth`, (d) the 28 hand-curated tags listed in `EXPECTED_TAGS` are all present, (e) `components.schemas.ApiError` declares the four-value code enum (`SESSION_ALREADY_ACTIVE`, `SESSION_ALREADY_FINISHED`, `SESSION_FINISHED`, `SET_NUMBER_DUPLICATE`) and `ApiError.FieldError` (or `ApiError$FieldError` or `FieldError`) is registered under `components.schemas`. This is the authoritative regression gate; the bump is correct iff these 5 tests stay green after Tasks 1-3.

4. **Maven Central evidence (captured at plan author time, 2026-05-09).**

   - SpringDoc 2.8.17's parent POM (`org.springdoc:springdoc-openapi:2.8.17`) tracks Spring Boot 3.4 / 3.5 compatibility per the upstream documentation (the project's compatibility matrix lists "SpringDoc 2.8.x: Spring Boot 3.4.x and 3.5.x"; this repo runs Spring Boot 3.5.14 per `pom.xml` line 10).

```java
    /**
     * Registers ApiError (and its nested FieldError) under components.schemas.
     *
     * <p>Normally SpringDoc 2.6.0 surfaces these via its
     * {@code GenericResponseService} scan of {@code @RestControllerAdvice}
     * exception handlers, but that path calls
     * {@code new ControllerAdviceBean(Object)}, a constructor Spring 6.2 removed.
     * We disable that scan with {@code springdoc.override-with-generic-response=false}
     * to keep /v3/api-docs from 500-ing, and manually re-register the error
     * schemas here so the OpenAPI consumers (and our integration test) still
     * see ApiError + ApiError.FieldError under components.schemas.
     */
    @Bean
    OpenApiCustomizer apiErrorSchemaCustomizer() {
        return openApi -> {
            Components components = openApi.getComponents();
            if (components == null) {
                components = new Components();
                openApi.setComponents(components);
            }
            ResolvedSchema resolved =
                    ModelConverters.getInstance().readAllAsResolvedSchema(ApiError.class);
            if (resolved == null) return;
            if (resolved.schema != null) {
                components.addSchemas(resolved.schema.getName(), resolved.schema);
            }
            if (resolved.referencedSchemas != null) {
                for (Map.Entry<String, Schema> entry : resolved.referencedSchemas.entrySet()) {
                    components.addSchemas(entry.getKey(), entry.getValue());
                }
            }
        };
    }
```
