<task type="auto">
  <name>Task 2: Add docker-compose.override.yml.example for local-dev tweaks</name>
  <files>docker-compose.override.yml.example</files>
  <action>
Create `docker-compose.override.yml.example` at the repo root. Compose v2 auto-merges `docker-compose.override.yml` (if present) on top of `compose.yml`, but `.example` suffix means operators copy and customize. Document at the top.

Content shape:

```yaml
# docker-compose.override.yml.example
# Copy to docker-compose.override.yml and edit. Compose auto-merges
# the override on top of compose.yml. The override file is gitignored.
#
# Common reasons to override:
#   - Lower resource limits for ARM/Raspberry Pi hosts
#   - Bind to a different interface than 127.0.0.1
#   - Add a local volume mount for development
#   - Enable the optional pg_dump sidecar (Phase 7)

services:
  db:
    deploy:
      resources:
        limits:
          cpus: "0.5"
          memory: 256M
        reservations:
          cpus: "0.1"
          memory: 64M

  backend:
    deploy:
      resources:
        limits:
          cpus: "1.0"
          memory: 512M
        reservations:
          cpus: "0.25"
          memory: 256M

  frontend:
    deploy:
      resources:
        limits:
          cpus: "0.5"
          memory: 192M
        reservations:
          cpus: "0.1"
          memory: 64M
```

Add the override pattern to `.gitignore` (ignore `docker-compose.override.yml` but TRACK `.example`):

```
# Compose local override (operator copies .example, gitignored)
docker-compose.override.yml
```

Do NOT include the actual sidecar service blocks (Phase 7 ships those in a separate config). Keep this file purely about resource tuning + example header doc.
