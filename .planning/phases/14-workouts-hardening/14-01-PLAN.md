<objective>
Close i-1 by fixing the cascade-id propagation bug in WorkoutDaysService that drops the `id` field from POST `/api/workout-plans/{planId}/days` and `/exercises` response bodies. Re-enable the six tests in WorkoutDaysIntegrationTest that were disabled around this bug, and add a regression assertion to the green-passing day-create test so a future return of the same root cause cannot pass undetected.

Purpose: Phase 13 audit (Section 4a) ranked Hibernate's `saveAndFlush(plan)` not propagating `@UuidGenerator` id assignment to a transient cascade-child as the most likely root cause of i-1, with explicit `daysRepo.saveAndFlush(day)` / `itemsRepo.saveAndFlush(item)` as the fix. Without this fix, the workouts feature surface returns response bodies that the frontend cannot use (no `id` to navigate to the new resource), and 6 of 8 WorkoutDaysIntegrationTest cases stay disabled, leaving the day/item lifecycle unverified in CI.
Output: Updated `WorkoutDaysService.createDay` and `WorkoutDaysService.addItem` using direct child-repo flushes, a new `WorkoutDayExerciseRepository`, six re-enabled tests, and one strengthened green test that explicitly asserts `$.id` presence.
</objective>
