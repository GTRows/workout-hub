<objective>
Extend `GET /api/metrics` with optional `from`/`to` `LocalDate` query parameters so the metrics UI can read date-windowed slices for chart rendering. Closes ROADMAP Phase 17 deliverable "time-series read endpoints for the metrics UI" and lifts ProjectBrief "Kilo grafigi (haftalik/aylik/tum zamanlar)" from Partial.

Purpose: The current `list` endpoint returns full history with no server-side filter. The frontend chart UI needs a server-side range read; client-side filtering of the full history wastes bandwidth and prevents efficient pagination later. The fix reuses the existing `idx_body_metrics_user_date` index, requires no schema change, and follows the existing `RequestParam` + Spring Data derived-query pattern used elsewhere in the codebase.

Output: 1 new repo method, 1 service signature/branch update, 1 controller signature update, 4 new integration tests (range hit, empty range, mixed-only-one, inverted). No migration. No DTO change.
</objective>

```java
@Transactional(readOnly = true)
public List<BodyMetricDto> list(UUID userId, LocalDate from, LocalDate to) {
    boolean fromSet = from != null;
    boolean toSet = to != null;
    if (fromSet ^ toSet) {
        throw new ResponseStatusException(HttpStatus.BAD_REQUEST,
                "from and to must be provided together");
    }
    if (fromSet && from.isAfter(to)) {
        throw new ResponseStatusException(HttpStatus.BAD_REQUEST,
                "from must not be after to");
    }
    List<BodyMetric> rows = fromSet
            ? repo.findByUserIdAndRecordedDateBetweenOrderByRecordedDateDesc(userId, from, to)
            : repo.findByUserIdOrderByRecordedDateDesc(userId);
    return rows.stream().map(MetricsService::toDto).toList();
}
```
