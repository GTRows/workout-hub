Append the following jobs to the existing `ci.yml` (alongside `backend` and `frontend`):

1. `gitleaks` - uses `gitleaks/gitleaks-action@v2`. Scans staged diff and full history. Reads `.gitleaks.toml` for allowlist (empty for now).

2. `trivy_fs` - uses `aquasecurity/trivy-action@0.28.0` in `fs` mode against the repo root. Severity threshold HIGH,CRITICAL.

3. `trivy_image` - matrix over `[backend, frontend]`. Each matrix entry builds the image via `docker build -t workouthub-{component}:ci ./{component}` then `aquasecurity/trivy-action` in `image` mode against the built tag. Severity HIGH,CRITICAL.

4. `compose_config` - runs `docker compose -f compose.yml config` with placeholder env vars exported inline (POSTGRES_PASSWORD=ci-test, APP_JWT_SECRET=ci-test-jwt-secret-32-bytes-min-0123456789, BIND_ADDR=127.0.0.1, BACKEND_PORT=8080, FRONTEND_PORT=3000, POSTGRES_PORT=5432, POSTGRES_USER=ci, POSTGRES_DB=ci, SPRING_DATASOURCE_URL=jdbc:postgresql://db:5432/ci, SPRING_DATASOURCE_USERNAME=ci, SPRING_DATASOURCE_PASSWORD=ci). Asserts the resolved YAML structure is valid.

5. `hadolint` - matrix over `[backend, frontend]`. Uses `hadolint/hadolint-action@v3.1.0` against `./{component}/Dockerfile`.

6. `actionlint` - uses `reviewdog/action-actionlint@v1` (or `rhysd/actionlint`) in failure-on-error mode.

7. `shellcheck` - runs `shellcheck` over `scripts/*.sh` if any exist; otherwise no-op (no `scripts/*.sh` exist yet, but operator may add them; the job can use `find scripts -name '*.sh' -print0 | xargs -0 -r shellcheck`).

Each new job runs on `ubuntu-latest`, has its own `actions/checkout@v4` step, and uses pinned action versions where possible. All gate the workflow's overall success.
