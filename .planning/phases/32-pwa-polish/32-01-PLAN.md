<objective>
Phase 32 (pwa-polish) per the v0.6 ROADMAP entry targets "install prompt, offline shell, service worker scope, app icon and manifest." Reconnaissance at plan time shows the icon + manifest + minimal service worker were partially shipped already:

- `frontend/public/manifest.webmanifest` is present with `name`, `short_name`, `display: standalone`, `start_url: /dashboard`, `theme_color: #0ea5e9`, `lang: tr`, and a 3-icon set (192 any, 512 any, 512 maskable).
- `frontend/public/icons/` ships `icon-192.png`, `icon-512.png`, `icon-maskable-512.png`, `apple-touch-icon.png`, plus the `source.svg` master.
- `frontend/public/sw.js` is the minimal service worker: `wh-shell-v1` cache, `/api/` bypass, navigation fallback to `/offline`, asset cache-first for non-API GETs.
- `frontend/src/components/service-worker-registrar.tsx` registers `/sw.js` after window load, prod-only, with the existing `service-worker-registrar.test.tsx` covering both branches.
- `frontend/src/app/layout.tsx` wires `metadata.manifest = "/manifest.webmanifest"`, `metadata.icons.{icon,apple}`, `metadata.appleWebApp`, and `viewport.themeColor = "#0ea5e9"`.
- `frontend/src/app/manifest.test.ts` already locks the manifest contract (name, short_name, display, theme_color, start_url, 192/512 any + 512 maskable icons).

Three concrete gaps remain that this sub-plan closes end-to-end:

1. **Missing `/offline` route.** `sw.js:5` precaches `["/offline", "/manifest.webmanifest", "/icons/icon-192.png"]` and `sw.js:34` falls back to `caches.match("/offline")` for failed navigations, but no `frontend/src/app/offline/page.tsx` exists. The current behaviour: on SW install, `cache.addAll(SHELL)` rejects (404 on `/offline`) and the entire install promise fails — `event.waitUntil(...)` rejects, the SW remains in `redundant` state, and the user gets ZERO offline shell coverage. This is a latent production bug shipped with the existing minimal SW. The fix is two-fold: (a) ship a real `/offline` route under `frontend/src/app/offline/page.tsx` (a server component, no client JS, no auth, no API calls — just a localized "you are offline" panel with a retry hint), (b) confirm the SW install succeeds against the new route via a vitest unit covering the precache contract.

2. **No install-prompt UX.** Browsers fire `beforeinstallprompt` on eligible PWAs, but Chrome/Edge defer the native UI until the page calls `event.prompt()`. The app currently does NOT capture the event nor surface an install button — installability is technically present but invisible to users. The fix is a small `InstallPromptCard` client component that:
   - Listens for `window.beforeinstallprompt`, calls `event.preventDefault()`, stores the deferred event in state.
   - Listens for `appinstalled` to clear the deferred event.
   - Renders nothing until a deferred prompt exists AND the user has not previously dismissed (localStorage flag `wh.installPromptDismissed` per Phase 25 storage convention).
   - When visible: a `Card` on the dashboard with the localized message + an "Install" `Button` (calls `event.prompt()`, awaits `event.userChoice`, clears state on either outcome) and a "Not now" dismiss button (sets the localStorage flag, hides for the session).
   - Mounted only inside the (app) shell — not on (auth) pages — by adding it to `frontend/src/app/(app)/dashboard/dashboard-client.tsx` (or a sibling slot in `(app)/layout.tsx` if the dashboard renders too late). Plan-locked: dashboard placement is the chosen home (visibility on first authenticated screen; the layout wrapper would also show it on every (app) route, which is too aggressive).

3. **Service-worker scope hardening + cache versioning.** Today `wh-shell-v1` is hardcoded. Two issues: (a) the SW does not bump the cache key on application updates (so a deployed change to the offline shell HTML is masked by the stale cache); (b) `self.skipWaiting()` + `self.clients.claim()` are called unconditionally — fine for a fresh install, but on update this can swap the SW out from under in-flight navigations. The fix is conservative:
   - Bump the cache constant to `wh-shell-v2` to drop the broken v1 cache (which never installed cleanly) on first deploy after this lands.
   - Keep `skipWaiting()` (low-traffic homelab app; we want the new SW to take over immediately) and `clients.claim()` (so the first navigation after install gets cached responses).
   - Add a precise `scope: "/"` declaration to the registration call (currently relies on default scope inference; making it explicit eliminates ambiguity if someone later moves `sw.js` under a subpath).
   - Add a unit test that loads `frontend/public/sw.js` as text and asserts: (a) cache constant matches `wh-shell-v2`, (b) the SHELL array contains `/offline`, `/manifest.webmanifest`, and at least one icon, (c) `/api/` paths are bypassed (regex match on the early-return guard).

The plan is intentionally bounded: pure frontend, no backend, no migrations, no Docker / compose / package.json changes (no new runtime deps). The SW lives in `public/`, the offline page is a tiny server component, the install prompt card uses the existing `Card`/`Button` shadcn primitives. The test gate runs entirely under `pnpm --filter ./frontend` (consistent with the local-Maven-gap memory note: backend mvn unavailable on this Windows host; backend untouched here).

This is the only sub-plan for Phase 32 — the four roadmap deliverables (install prompt, offline shell, SW scope, app icon + manifest) are addressed in one cohesive change. Icon + manifest are already shipped and only get a cross-check in the verification gate; install prompt and offline shell are the net-new surfaces. After 32-01 ships and CI is green: Phase 32 closes; ROADMAP advances to Phase 33 (web-push-notifications). If during execution the install-prompt UX expands beyond a single card (e.g. an iOS-specific instructions sheet for Safari, which does NOT fire `beforeinstallprompt`), the executor calls a halt and the orchestrator schedules a 32-02 follow-up; the plan-locked scope here covers Chromium-family browsers only, with iOS deferred to a Phase 32-02 if desired.
</objective>

```tsx
"use client";

import { useEffect, useState } from "react";
import { useTranslations } from "next-intl";
import { Button } from "@/components/ui/button";
import {
  Card,
  CardContent,
  CardDescription,
  CardFooter,
  CardHeader,
  CardTitle,
} from "@/components/ui/card";

interface BeforeInstallPromptEvent extends Event {
  readonly platforms: string[];
  readonly userChoice: Promise<{ outcome: "accepted" | "dismissed"; platform: string }>;
  prompt(): Promise<void>;
}

const DISMISS_KEY = "wh.installPromptDismissed";

function isStandalone(): boolean {
  if (typeof window === "undefined") return false;
  return window.matchMedia?.("(display-mode: standalone)").matches ?? false;
}

function isDismissed(): boolean {
  if (typeof window === "undefined") return false;
  try {
    return window.localStorage.getItem(DISMISS_KEY) === "1";
  } catch {
    return false;
  }
}

export function InstallPromptCard() {
  const t = useTranslations("pwa");
  const [deferred, setDeferred] = useState<BeforeInstallPromptEvent | null>(null);
  const [dismissed, setDismissed] = useState<boolean>(true);

  useEffect(() => {
    setDismissed(isDismissed() || isStandalone());

    const onBeforeInstall = (e: Event) => {
      e.preventDefault();
      setDeferred(e as BeforeInstallPromptEvent);
    };
    const onInstalled = () => {
      setDeferred(null);
      try {
        window.localStorage.removeItem(DISMISS_KEY);
      } catch {
        /* ignore */
      }
    };

    window.addEventListener("beforeinstallprompt", onBeforeInstall);
    window.addEventListener("appinstalled", onInstalled);
    return () => {
      window.removeEventListener("beforeinstallprompt", onBeforeInstall);
      window.removeEventListener("appinstalled", onInstalled);
    };
  }, []);

  if (!deferred || dismissed) return null;

  const onInstall = async () => {
    await deferred.prompt();
    await deferred.userChoice;
    setDeferred(null);
  };

  const onDismiss = () => {
    try {
      window.localStorage.setItem(DISMISS_KEY, "1");
    } catch {
      /* ignore */
    }
    setDismissed(true);
  };

  return (
    <Card>
      <CardHeader>
        <CardTitle>{t("installTitle")}</CardTitle>
        <CardDescription>{t("installDescription")}</CardDescription>
      </CardHeader>
      <CardContent />
      <CardFooter className="flex gap-2">
        <Button onClick={onInstall}>{t("installButton")}</Button>
        <Button variant="outline" onClick={onDismiss}>
          {t("installDismiss")}
        </Button>
      </CardFooter>
    </Card>
  );
}
```
