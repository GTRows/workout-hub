**Tech stack carried from v0.3 / v0.4:** Next.js 15.1.x (App Router, RSC by default), React 19, TypeScript strict, Tailwind v4, shadcn/ui copy-in primitives, TanStack Query 5.x, react-hook-form + Zod, Dexie 4.x for IndexedDB, next-intl 3.26.x (default locale `tr`), Playwright + Vitest + Testing Library, pnpm 9.15.x, ESLint flat config.

**Backend contract carried from v0.4:**
- SpringDoc OpenAPI exposed at `/v3/api-docs` (paths-to-match `/api/**`).
- JWT bearer auth default; `AUTH_MODE=forward-auth` opt-in.
- `ApiError` envelope with typed `code` catalog (4 known values: `SESSION_ALREADY_ACTIVE`, `SESSION_ALREADY_FINISHED`, `SESSION_FINISHED`, `SET_NUMBER_DUPLICATE`); branch on `status` + `code`, never `message`.
- `ClaudeSummaryDto` is per-record `@JsonNaming(SnakeCaseStrategy)`; full-export DTOs stay camelCase.
- `SessionSet.isPr` is persisted via V27; `FullExportDto.SetRow` carries `isPr` as the 9th tuple field; importer recomputes per (user, exercise) pair as a safety net.
- Body-metrics upsert returns `201` on insert, `200` on replace (date-keyed UNIQUE on `(user, date)`).
- `clientSetId` idempotent replay suppresses `newPr`.
- Frontend `/api/metrics` exposes Node process metrics only (i-4 still open: per-request HTTP histograms deferred to v0.6 Phase 35).

**Established frontend patterns (carried from pre-GSD + v0.3):**
- App Router route groups: `(auth)/` for unauthenticated entry, `(app)/` for the authenticated shell.
- Server Components by default; `"use client"` only when state, effects, or browser APIs are needed.
- API access goes through `frontend/src/lib/api/client.ts` (no ad-hoc `fetch` in components).
- Zod schemas under `frontend/src/lib/api/schemas.ts` mirror the API contract.
- Forms via react-hook-form + Zod resolvers.
- All user-facing strings via `next-intl` (`messages/{en,tr}.json`); default locale `tr`.
- Offline session queue lives in `frontend/src/lib/offline/session-set-queue.ts` (Dexie store).
- Tailwind v4 utility-first; design tokens in `tailwind.config.ts` (or v4 CSS @theme); shadcn primitives copied into `components/ui/`.

**Constraining decisions:**
- ROADMAP outline (Phases 22-30) was scoped before this audit ran. The audit's job is to recommend whether each outlined phase stays as-is, splits, merges, or shifts to v0.6 / v1.0. The audit does NOT rewrite ROADMAP.md - that is a follow-up planning step taken by `/gsd:insert-phase` or a manual ROADMAP edit driven by Section 5 of the audit.
- i-6 (Next 15 -> 16 major bump) and i-5 (next-intl 3 -> 4) remain deferred. v0.5 stays on Next 15.x and next-intl 3.x.
- No backend changes in v0.5. The audit may identify backend gaps surfaced by frontend integration, but those become candidate v0.6 issues, not v0.5 work.
- Read-only: no `pnpm install`, no code edits, no dependency bumps. The only file written by this plan is the audit document.

**Issues being addressed (informational, not closed by this audit):**
- i-4: frontend per-request HTTP metrics (deferred to v0.6 Phase 35) - audit notes current `/api/metrics` shape.
- i-6: Next 16 major bump (deferred) - audit confirms 15.x line is current.

**Out of scope for this plan:**
- Editing any `.ts`, `.tsx`, `.json`, `.css`, `.js` file under `frontend/`.
