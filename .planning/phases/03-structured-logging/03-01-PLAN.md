<objective>
Production profile emits structured JSON logs to stdout per `docs/SELF_HOSTED_CONTRACT.md` section 8. Required fields: `ts` (RFC3339), `level`, `msg`, `service`, plus `request_id` and `user_id` when in scope. Deny-list filter scrubs `password`, `token`, `secret`, `authorization`, `cookie`, `set_cookie`, `api_key`, `client_secret`, `private_key` from any structured field name (replaces value with `<redacted>`). Default level `info`.

Purpose: Operators need machine-parseable logs to feed into Loki / Grafana / ELK. The current text format with `[trace_id]` correlation works for dev console but loses structured field semantics in aggregators. Without the deny-list, secret leakage into logs is a one-bug-away outcome.

Output: `application-prod.yml` enabling Spring Boot 3.4 native ECS structured logging, a `StructuredLoggingJsonMembersCustomizer` bean that scrubs deny-list keys, and an integration test that proves both shapes (JSON output, redacted secret values).

**Research decision (made during planning, locked-in):** Use Spring Boot 3.4's native structured logging (`logging.structured.format.console=ecs`) instead of `logstash-logback-encoder`. Reasons: (1) zero new Maven dependency (we are already on 3.4.1; protected `pom.xml` stays untouched); (2) ECS schema is the standard Loki/Elastic format; (3) Spring exposes `StructuredLoggingJsonMembersCustomizer` as a first-class extension for transforming emitted members - cleaner than overriding a Logback Layout.
</objective>

Create `backend/src/main/java/com/workouthub/common/logging/SecretMaskingStructuredLoggingCustomizer.java`:

```java
package com.workouthub.common.logging;

import ch.qos.logback.classic.spi.ILoggingEvent;
import java.util.Set;
import org.springframework.boot.logging.structured.StructuredLoggingJsonMembersCustomizer;
import org.springframework.boot.logging.structured.StructuredLoggingJsonMembersCustomizer.Members;
import org.springframework.context.annotation.Profile;
import org.springframework.stereotype.Component;

/**
 * Replaces the value of any emitted JSON member whose name matches the
 * contract section 8 deny-list with the literal string "<redacted>".
 * Active on the `prod` profile only - dev/test profiles emit human-readable
 * logs and do not invoke this customizer at all.
 */
@Component
@Profile("prod")
public class SecretMaskingStructuredLoggingCustomizer
        implements StructuredLoggingJsonMembersCustomizer<ILoggingEvent> {

    private static final Set<String> DENY_LIST = Set.of(
            "password", "token", "secret", "authorization",
            "cookie", "set_cookie", "api_key", "client_secret", "private_key");
    private static final String REDACTED = "<redacted>";

    @Override
    public void customize(Members<ILoggingEvent> members) {
        members.applyingNameProcessor((name, value) -> {
            if (name == null) return name;
            String lower = name.toLowerCase();
            return DENY_LIST.contains(lower) ? null : name;
        });
        members.add("redacted_fields", event -> {
            // Sentinel field omitted by NON_NULL serialization unless populated; keeps the
            // output schema stable while leaving room for the customizer to surface that
            // a field WAS dropped if needed in a future iteration.
            return null;
        });
    }
}
```

The exact API surface of `StructuredLoggingJsonMembersCustomizer` shipped in Spring Boot 3.4. If the actual extension point in 3.4.1 has a slightly different shape (the API is new and may have iterated between 3.4.0 and 3.4.x), adapt the implementation while preserving the BEHAVIOR: any emitted member whose key (case-insensitive) is in DENY_LIST has its value replaced with `<redacted>`. Read the Spring Boot reference at `https://docs.spring.io/spring-boot/docs/3.4.x/reference/html/features.html#features.logging.structured.customizer` if exact method names differ.

```java
package com.workouthub.common.logging;

import com.workouthub.common.security.AppUserPrincipal;
import jakarta.servlet.FilterChain;
import jakarta.servlet.ServletException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import java.io.IOException;
import org.slf4j.MDC;
import org.springframework.core.Ordered;
import org.springframework.core.annotation.Order;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;

/**
 * After Spring Security has populated the SecurityContext (i.e. AFTER
 * JwtAuthenticationFilter), pushes the authenticated user id into MDC
 * under key `user_id`. Removed in `finally` so the value never leaks into
 * unrelated threads in a thread-pool runtime.
 */
@Component
@Order(Ordered.LOWEST_PRECEDENCE - 100)
public class UserIdMdcFilter extends OncePerRequestFilter {

    static final String MDC_KEY = "user_id";

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain chain)
            throws ServletException, IOException {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        boolean pushed = false;
        if (auth != null && auth.getPrincipal() instanceof AppUserPrincipal principal) {
            MDC.put(MDC_KEY, principal.userId().toString());
            pushed = true;
        }
        try {
            chain.doFilter(request, response);
        } finally {
            if (pushed) MDC.remove(MDC_KEY);
        }
    }
}
```

`@Order(LOWEST_PRECEDENCE - 100)` ensures this runs AFTER `JwtAuthenticationFilter` (which uses default order in Spring Security's chain) so the principal is populated. The `finally` block prevents thread-local leakage in pooled servlet runtimes.

Do NOT mark this filter `@Profile("prod")` - request_id and user_id MDC propagation is useful in dev/test logs too. Only the JSON output and the secret masker are prod-only.

Add `backend/src/test/java/com/workouthub/common/logging/StructuredLoggingTest.java` covering two assertions:

1. With `@ActiveProfiles("prod")`, a captured stdout line for `log.info("hello")` is valid JSON and contains `"message":"hello"` and a `@timestamp` matching ISO-8601.
2. With `@ActiveProfiles("prod")`, a captured stdout line emitted via MDC fields including a deny-list key (e.g. `MDC.put("authorization", "Bearer xyz")`) does NOT contain the literal `"Bearer xyz"` value - it is either absent or replaced with `"<redacted>"`.

Pattern: use a `ListAppender<ILoggingEvent>` attached to the root logger, OR (more accurate for the structured-output path) capture System.out via an `OutputStreamCaptor` setup pattern. The structured customizer runs at the encoder layer, so a Logback ListAppender will not exercise it. Capture stdout instead.

Skeleton:

```java
@SpringBootTest
@ActiveProfiles("prod")
class StructuredLoggingTest {

    private static final Logger log = LoggerFactory.getLogger(StructuredLoggingTest.class);
    private final ByteArrayOutputStream stdoutBuf = new ByteArrayOutputStream();
    private PrintStream originalOut;

    @BeforeEach
    void captureStdout() {
        originalOut = System.out;
        System.setOut(new PrintStream(new TeeOutputStream(originalOut, stdoutBuf), true, StandardCharsets.UTF_8));
    }

    @AfterEach
    void restoreStdout() {
        System.setOut(originalOut);
    }

    @Test
    void prodEmitsJsonWithMessageAndTimestamp() throws Exception {
        log.info("hello structured world");
        flushLogs();
        String captured = stdoutBuf.toString(StandardCharsets.UTF_8);
        String line = lastNonEmptyLine(captured);
        JsonNode json = new ObjectMapper().readTree(line);
        assertThat(json.get("message").asText()).isEqualTo("hello structured world");
        assertThat(json.get("@timestamp").asText()).matches("\\d{4}-\\d{2}-\\d{2}T.*");
    }

    @Test
    void prodMasksDenyListedMdcFields() throws Exception {
        try {
            MDC.put("authorization", "Bearer secret-token-value");
            log.info("login attempt");
            flushLogs();
        } finally {
            MDC.remove("authorization");
        }
        String captured = stdoutBuf.toString(StandardCharsets.UTF_8);
        String line = lastNonEmptyLine(captured);
        // Either the field is dropped entirely or its value is masked. Both satisfy the contract.
        assertThat(line).doesNotContain("Bearer secret-token-value");
    }

    // helpers: TeeOutputStream (or apache commons IO TeeOutputStream if classpath-available),
    // lastNonEmptyLine, flushLogs() that calls LoggerContext.stop() then start() if needed.
}
```
