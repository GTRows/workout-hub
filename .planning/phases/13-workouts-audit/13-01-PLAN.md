**Tech stack available (carried from v0.3):** Java 21, Spring Boot 3.5.x, Spring Web, Spring Data JPA, Hibernate `@UuidGenerator`, Jackson with `serializationInclusion = NON_NULL`, Flyway migrations, JUnit 5 + Testcontainers Postgres, Spring Security with JWT filter and `AUTH_MODE=forward-auth` opt-in.

**Established patterns (carried from v0.3):**
- Feature-sliced packages (`workouts/`, `auth/`, `users/`, etc.).
- Controller -> Service -> Repository, transactions on services, DTOs at HTTP boundary.
- Validation via `jakarta.validation` on request DTOs.
- Flyway migrations are immutable; new schema = new `V<n>__*.sql`.
- Tests: JUnit 5 + Testcontainers, no H2.

**Constraining decisions:**
- v0.3 contract section 7: built-in JWT default, no OIDC client. Endpoint auth requirements must reflect this.
- `ddl-auto: validate` - schema cannot drift; migrations are the only source of truth.

**Issues being addressed:**
- i-1: WorkoutDaysIntegrationTest helper NPE on response `id` field (6 disabled tests in `addItemsAndReorderCloseNoGaps`, `deleteDayCascadesItems`, `deleteItemRenumbersRemaining`, `duplicateDayOfWeekReturns409`, `reorderWithIncompleteListReturns409`, `updateItemPatchesFields`). Hypothesis candidates noted in ISSUES.md: mapper running before flush, missing `WorkoutPlan.addDay` back-reference, Jackson NON_NULL dropping unset id.
- i-2: FullExportImportIntegrationTest.importRoundTripPreservesPlansFromExport returns `plansInserted == 0`. Same root-cause family as i-1 suspected.

**Out of scope for this plan:**
- Writing Java fixes (Phase 14).
- Adding new endpoints (Phase 15+).
- Touching session/metric/export packages beyond reading the export-import test path for i-2.
