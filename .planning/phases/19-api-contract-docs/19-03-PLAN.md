Audit explicitly rejects method-level `@Tag` aggregation — keeping tags at class level is the audit's explicit boundary verdict.
- **28 user/admin-facing controllers covered.** The 31-controller catalog from audit Section 1A minus the 3 operator controllers (`HealthController` at `/livez,/healthz`; `PrometheusMetricsController` at `/metrics`; `ScaleWebhookController` at `/api/webhooks/scale`). - **operationId disambiguation: dual SessionsController only, all 7 mapped methods explicit.** Audit Section 1B + 5B records the dual-class concern. SpringDoc 2.x's default operationId generator uses `<methodName>` (with a numeric suffix on collision in scan order). The two classes share simple class name `SessionsController` — when both are scanned in the same OpenAPI surface, SpringDoc's collision resolver may produce `list` for the first and `list_1` for the second (or vice versa, scan-order dependent). Both classes' methods get explicit operationIds in this plan to make the document deterministic regardless of scan order:
  - `sessions.SessionsController` (5 methods): `start` -> `startWorkoutSession`; `active` -> `getActiveWorkoutSession`; `finish` -> `finishWorkoutSession`; `history` -> `listWorkoutSessionHistory`; `detail` -> `getWorkoutSession`.
  - `users.SessionsController` (2 methods): `list` -> `listUserRefreshSessions`; `revoke` -> `revokeUserRefreshSession`.
  Naming convention: verb + qualifier + entity-singular/plural. Verbs reflect HTTP intent (`get/list/start/finish/revoke`). The plan does NOT extend explicit operationIds to the rest of the 28 controllers — SpringDoc's default works for them since the simple class names are unique once `@Tag` has separated the namespaces (the audit's verdict in Section 6 `defer` at line `:670` is "per-method `@Operation` annotations beyond the two collision spots: low ROI on the v0.4 budget").

The two tags disambiguate the consumer-facing grouping; the operationId disambiguation is a secondary client-codegen-friendliness concern.
- **No `@Operation(summary = ...)` or `@Operation(description = ...)` in this plan.** Only `@Operation(operationId = "...")` on the 7 dual-SessionsController methods. SpringDoc auto-derives a serviceable summary from the method name; rich per-method documentation is a v1.0 polish item per audit Section 6 `defer`.
