<objective>
Bring `compose.yml` into structural compliance with `docs/SELF_HOSTED_CONTRACT.md` sections 3.2-3.4: parametric port bindings (no implicit `0.0.0.0`), an explicit named network, and bind-mount volumes under `./data/<component>/` instead of named Docker volumes.

Purpose: Eliminate the two highest-impact contract violations operators see at first run - silent exposure on every host interface and invisible-to-backup-tools state storage. Without these, the project cannot be safely operated by anyone.

Output: Updated `compose.yml`, updated `.gitignore`, new `data/` directory tree with `.gitkeep` files, ready for a clean operator-side `docker compose up -d`.
</objective>

**Tech stack available:** Docker Compose v2, PostgreSQL 16-alpine, Spring Boot 3 backend on `:8080`, Next.js 15 frontend on `:3000`.

**Constraining decisions (from STATE.md):**
- `BIND_ADDR` parametric, default `127.0.0.1` (loopback). Tailnet IP injected at deploy time, never committed to repo.
- Two GHCR images planned (backend + frontend); Compose still builds locally for now.
- No reverse proxy, TLS, or operator-specific topology in this repo - operator brings their own.

**Issues being addressed:**
- CONCERNS i-A (port bindings default to 0.0.0.0)
- CONCERNS i-B (named volume `db_data` invisible to backup tools)
- CONCERNS i-C (no named network; relies on default bridge)

**Note on protected files:** `compose.yml` is in the project's protected-edit list (`.claude/hooks/pre_guard_release_files.py`). Editing it during execution will trigger a confirmation prompt - that is expected, approve and continue.

<task type="auto">
  <name>Task 1: Parametrize port bindings and add named network</name>
  <files>compose.yml</files>
  <action>
Rewrite the `ports:` blocks of all three services to follow the `"${BIND_ADDR:-127.0.0.1}:${SERVICE_PORT:-DEFAULT}:CONTAINER_PORT"` pattern from contract section 3.2. Use these env var names so they are unambiguous per service:
- `db.ports`: `"${BIND_ADDR:-127.0.0.1}:${POSTGRES_PORT:-5432}:5432"` (keep existing POSTGRES_PORT name; only add BIND_ADDR prefix)
- `backend.ports`: `"${BIND_ADDR:-127.0.0.1}:${BACKEND_PORT:-8080}:8080"` (rename existing SERVER_PORT to BACKEND_PORT for clarity at the compose level; the backend application still reads `SERVER_PORT` internally)
- `frontend.ports`: `"${BIND_ADDR:-127.0.0.1}:${FRONTEND_PORT:-3000}:3000"` (replace the literal `"3000:3000"`)

Add an explicit network block at the bottom of the file per contract section 3.3:

```yaml
networks:
  workouthub-net:
    name: workouthub-net
```

Attach every service to it via `networks: [workouthub-net]`.

Do NOT touch healthchecks, resource limits, depends_on conditions, or volumes here - those are scoped to Plan 01-02 and 01-01 Task 2 respectively. Keep the diff focused.

Do NOT default `BIND_ADDR` to anything other than `127.0.0.1`. The contract is explicit: a fresh `docker compose up` must be safe (loopback only). Operators opt into LAN/VPN exposure by setting BIND_ADDR in their `.env`.
  </action>
  <verify>
`docker compose -f compose.yml config` exits 0 and the resolved YAML shows the new network attached and all three port bindings prefixed with `127.0.0.1:` when run without an `.env` BIND_ADDR override.
  </verify>
  <done>
- All three services bind to `127.0.0.1` by default.
- `workouthub-net` declared and attached to all three services.
- No service uses the implicit default bridge network.
- `compose config` validates.
  </done>
</task>

<task type="auto">
  <name>Task 2: Switch DB to bind mount under ./data/postgres/</name>
  <files>compose.yml, .gitignore, data/postgres/.gitkeep, data/.gitkeep</files>
  <action>
Per contract section 3.4, replace the named volume with a bind mount:

In `compose.yml`:
- Change `db.volumes` line from `- db_data:/var/lib/postgresql/data` to `- ./data/postgres/:/var/lib/postgresql/data`.
- Delete the top-level `volumes:` block entirely (the only entry was `db_data:`).

In `.gitignore`, add a `data/` rule under the existing "Environment and secrets" section. Use this exact addition (with a leading section comment for context):

```
# Self-hosted bind-mount data root (operator state - never committed)
data/
!data/.gitkeep
!data/postgres/.gitkeep
```

The negation lines are required so the placeholder `.gitkeep` files stay tracked while everything else under `data/` is ignored. This makes the directory tree exist on a fresh clone.

Create the placeholder files:
- `data/.gitkeep` (empty)
- `data/postgres/.gitkeep` (empty)

Do NOT attempt any data migration. Per STATE.md decisions, the local DB starts fresh on this contract migration. The operator-facing migration step lives in `docs/MIGRATION.md` (Phase 9 of the milestone).

Do NOT add `data/uploads/` or other component directories yet - that comes when those components land. Keep this scoped to Postgres.
  </action>
  <verify>
- `docker compose -f compose.yml config` exits 0.
- `git status` shows `data/.gitkeep` and `data/postgres/.gitkeep` as new files.
- `git check-ignore data/postgres/anyfile` exits 0 (proves the directory contents are ignored).
- `git check-ignore data/postgres/.gitkeep` exits 1 (proves the .gitkeep is NOT ignored).
  </verify>
  <done>
- `compose.yml` references `./data/postgres/` bind mount; top-level `volumes:` block removed.
- `.gitignore` ignores `data/` contents but tracks `.gitkeep` files.
- `data/.gitkeep` and `data/postgres/.gitkeep` exist and are tracked.
- `compose config` validates.
  </done>
</task>
